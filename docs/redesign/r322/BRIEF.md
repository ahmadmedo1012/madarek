## 3. THE CRITIQUE RUBRIC (replaces "parity score" as the definition of done)
Three independent reviewer agents (not the authors) score each section/page at each breakpoint, 0–10 each, mean ≥ 9 and no category < 8:
1. **Hierarchy** — what is read first/second/third is obvious; one focal point per screen.
2. **Grid & alignment** — every edge on the shared 12-col rem grid; no orphan blocks; optical alignment of mono labels and rules.
3. **Spacing rhythm** — only values from the spacing scale (§4); no voids > 1.5× padding; no cramped pairs.
4. **Typography** — one display scale, one body scale, mono for labels only; weights restrained; line length 40–75 characters (Arabic 35–65); no one-word lines; correct Arabic shaping; no tashkeel in display; no letter-spacing on Arabic.
5. **Material & colour** — paper/ink/orange used like Heron (orange only as an accent ≤ 5 % of area per screen except designed full-bleed moments); consistent grain/hairlines/dashed frames; dark pair coherent.
6. **Density & restraint** — nothing decorative without function; no jargon, debug or duplicate text; no chips/tooltips/stickers unless Heron has the equivalent.
7. **Consistency** — the same component looks identical everywhere (buttons, inputs, chips, cards, tables, tabs, menus, dialogs).
8. **Motion & scroll feel** — see §5; interactions feel the same as Heron's (timing, easing, scrub, pinning, inertia).
9. **Polish** — nothing clipped/overlapping/blurry/misaligned by 1 px; hover/active/focus states complete; empty/loading/error states designed.
10. **Responsiveness** — designed, not shrunk, at 320/360/390/430/768/820/1024/1180/1440/1920, portrait + landscape.
Reviewers must load and apply these skills before scoring: **pbakaus/impeccable** (`critique`, `polish`, `distill`, `adapt`, `harden`, `clarify`, `animate`), **vercel-labs `web-design-guidelines`**, **uizze `anti-ui-slop`**, **anthropics `frontend-design`**, **emilkowalski `review-animations`** (motion), `ui-ux-pro-max`, `design-md`. Each review is a written report (what works, the single biggest problem, numbered defects with file/selector) saved in BOARD.md; a bare number without defects is rejected.
