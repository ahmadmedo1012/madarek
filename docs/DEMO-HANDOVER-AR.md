## ١) سيناريو العرض (١٥ دقيقة)

1. **المنصة من الخارج** (١ د): `madarek-app.vercel.app` — صفحة التعريف والكليات.
2. **دخول الطالب** (٣ د): `student@test.ly` / `12345678` — اللوحة، المقررات، محاضرة مع نقاط تفتين، سؤال للمساعد الذكيّ (سيجيب Gemini أو Groq تلقائيًا).
3. **دخول الأستاذ** (٣ د): `teacher@test.ly` — الحضور والغياب، الدرجات، متابعة مخاطر الطلاب.
4. **المسجل العام** (٤ د): `registrar@test.ly` — دليل الأشخاص (بحث بالاسم والهاتف والرقم الجامعي)، ملف الطالب (صورة + وثائق)، استيراد Excel بوضع الفحص.
5. **الجودة** (٢ د): `quality@test.ly` — طابور مراجعة الاختبارات.
6. **الجوال** (٢ د): افتح APK على جوّالك — نفس الحساب، الإشعار التجريبي من إعدادات المنصّة، ثم أغلق التطبيق واطلب إعلانًا — يصل مقفلًا خلال ثوانٍ.

## ٢) النشر والتراجع

- **النشر**: دفع أي التزام إلى `main` → Vercel ينشر تلقائيًا (دقيقة–ثلاث). لا خطوات يدوية.
- **التراجع**: لوحة Vercel → المشروع `madarek` → Deployments → أي نشر سابق → قائمة ⋯ → **Promote to Production** (ثوانٍ، بلا بناء). القاعدة: لا نشر جديد فوق حادث — رجّع ثم صحّح.
- **نسخ القاعدة (Neon)**: كل «فرع» في Neon هو لقطة كاملة قابلة للاستعادة لحظيًا. من الوحدة: أنشئ فرعًا من `main` بلقطة كاملة؛ وللاستعادة إلى لحظة سابقة أنشئ فرعًا مع تحديد **الزمن** (PITR — مثبّت عمليًا في R357: سجل حُذف ثم عاد بالضبط كما كان عند دقيقة محددة). مدة الاستعادة المتاحة في الخطة المجانية تكفي لاكتشاف أي خطأ خلال ساعات.
- **نسخة المشغّل (pg_dump)**: `node scripts/db-backup.mjs` + `node scripts/db-restore.mjs` (يتطلبان `pg_dump`/`pg_restore` على جهازك — ليست في بيئة الوكيل؛ المنطق مثبّت بالاختبارات).
- الرابط الاحتياطي: `madarek-nine.vercel.app` يخدم نفس الإنتاج دائمًا.

## ٢ب) بيانات العرض (فرع demo-dataset في Neon)

- **ما هو**: فرع مستقل في Neon فيه بيانات العرض الكاملة — المؤسستان الوهميّتان (جامعة مدارك النموذجية + الأندلس) مع **٤٤٠ طالبًا وهميًا** (٤٤٠ بريد `bulk*@demo.madarek.ly` + مقاعد `@test.ly` نفسها بكلمة `12345678`) — لا يمسّ الإنتاج أبدًا (السكربت يرفض الرفض الصريح).
- **التعبئة/التصفير بأمر واحد** (من جذر المستودع):
  ```bash
  DATABASE_URL='<رابط فرع demo-dataset من وحدة Neon>' node scripts/qa/demo-dataset.mjs          # تعبئة (تُنشئ كل شيء)
  DATABASE_URL='<الرابط>' node scripts/qa/demo-dataset.mjs --reset                             # تصفير جراحي للبيانات المضافة فقط
  ```
- **لتشغيل العرض عليه**: أنشئ نشرًا تجريبيًا في Vercel (Deployments → أي نشر → ⋯ → Promote إلى بيئة preview، أو متغير `DATABASE_URL` مؤقت) — أو جرّبه محليًا: `DATABASE_URL='<الرابط>' npm --prefix backend run dev`.
- الإنتاج نفسه فيه نفس المقاعد والبيانات المنسّقة (بدون الدفعة الكبيرة) — العرض المعتاد يبقى على `madarek-app.vercel.app`.

## ٥) الطريق بعد موافقة الجامعة

1. **نطاق خاص** (مثل madarek.ly) — سجّله ثم أخبر الوكيل: يوم واحد يقلب كل الروابط.
2. **توثيق البريد على النطاق** — سجلات SPF/DKIM/DMARC جاهزة في `docs/MAIL.md` (نسخ + لصق).
3. **Apple Developer** (99$/سنة) — يفتح iOS + الإشعارات (الأمر كله جاهز تقنيًا).
4. **حسابات موظفين حقيقيين** — الاستيراد من Excel جاهز مع وضع الفحص.
5. **Vercel Pro** قبل أي تشغيل تجاري فعلي.

## ٦) ما ينتظر قرارك فقط (مفتوح عن قصد)

- تسجيلات DNS + قرار نطاق البريد.
- جدول المقاعد غير المحسومة (هل يحتاج الطيار حسابات أولياء أمور؟ هل «معيد» مقعد مطلوب؟).
- تأكيد الإشعار على جوّالك فعليًا (٥ خطوات في `docs/PUSH-FIREBASE-CHECKLIST.md`).
