# 13 — الصيانة والإدارة

## الروتين اليومي/الأسبوعي (مدير المنصة)

| المهمة | كيف | أين تتحقق |
|---|---|---|
| مراقبة الصحة | فحص `/api/v1/health` وسجلات Render | `{ ok: true }` + `dbLatencyMs` معقولة |
| التنبيهات التشغيلية | `/owner/alerts` — صفوف `OperationalAlert` (5xx/DB، خنق 5 دقائق) وتحديدها «حُلَّت» | `owner.routes.ts` |
| سجل النشاط | `/owner/activity` (AuditLog) بعد أي إداري غامض | عنوان عربي لكل إجراء |
| أعلام الميزات/الإعدادات | `/owner/settings` + `/owner/feature-flags` (`PlatformSetting`, `FeatureFlag`) | تعمل حيًا دون نشر |

## ما يديره النظام تلقائيًا (لا تتدخل)

- **مزامنة حقائق الجامعة** يوميًا (`zu-sync`) بسجل `SyncRun` وحرس تزامن
  مع الزناد اليدوي في `/admin/sync`.
- **تسريح سجلات الدخول** أقدم من 180 يومًا (دفعات 5000، سقف يومي) —
  نمو الاحتفاظ مضبوط.
- ترحيلات الإنتاج تُطبق تلقائيًا في بناء كل نشر (`migrate deploy`).

## مهام دورية موصى بها (كل بضعة أشهر)

1. **ترقية الاعتماديات بعناية**: الإصدارات مثبتة بالدقة؛ حدّث مجموعة
   واحدة، شغّل الحزمة كاملة (`lint/typecheck/test/build`)، ثم ادفع.
   لا تحدّث `prisma` و`@prisma/client` إلا معًا وبنفس الإصدار.
2. **مراجعة المفاتيح**: دورة تبديل `JWT_*` = إخراج كل الجلسات (bump
   غير ممكن عبر البيئة — تغيير السر يبطل كل التوكنات القديمة). خطط
   لنافذة صيانة.
3. **نسخ احتياطي**: لا إجراء موثق داخليًا — اعتمد ميزات Neon ( PITR /
   فروع) ووثّق خطوات استعادة مكتوبة لفريقك؛ اختبار الاستعادة مرة واحدة
   على الأقل.
4. **مراجعة الفجوات الموثقة** في [16](16-decisions-and-limitations.md)
   (baseline جرد الأسطح، i18n، جدول RefreshToken، مخزن حدود معدل مشترك).

## إدارة تغييرات المخطط (دورة كاملة)

```bash
# على فرع، بعد تعديل backend/prisma/schema.prisma:
npm run db:migrate            # على بيئة تطوير بقاعدة حية — يولد ترحيلًا جديدًا
npm test && npm run typecheck # لا تنكسر دوال القرار النقية
# أرفق ملف migrations/<stamp>_<name>/migration.sql في الـPR كما هو
```

- الإنتاج يطبقها في نشر `main` القادم تلقائيًا (migrate deploy).
- الترحيلات إضافية؛ لا تعدّل ترحيلًا مطبقًا ولا تعيد ضبط `_prisma_migrations`.
- ترحيل بيانات كبيرة (backfill): اتبع نموذج `20260929000000_progress_truth_backfill`
  (SQL دفعات آمنة).

## إدارة المحتوى والمستخدمين (أدوار)

- الأدوار والحالات: `/owner/users` أو `/admin/permissions/:id` — كل
  تعديل يمر بحراس الحاكمية ويكتب تدقيقًا ويرفع `tokenVersion`.
- إعادة بذر بيئة تطوير: `npm run db:seed` — تذكر أنها تمسح
  الإعلانات/المسابقات/الأحداث وتعيد كلمات demo (انظر
  [07-database](07-database.md)).
- ملفات البحوث الحالية مُقدَّمة في `backend/storage/papers/` عبر المراجعات
  — أي إضافة تتم بطلب مخول، لا يدويًا على خادم الإنتاج (قرص زائل).

## جولات التغيير (أعراف rNNN)

- كل جولة = دفعة متماسكة موثقة في `CHANGELOG.md` بلغة المستخدم (عربي)
  + تفاصيلها في سجل الالتزامات؛ الترقيم rNNN يتصاعد (`CONTRIBUTING.md`).
- حدّث `CHANGELOG.md` في نفس الـPR عند تغيير يلمس المستخدم.
- بعد أي جولة تصميم: `DESIGN.md` يُحدَّث من `tokens.css` (tokens هي
  المصدر)، وبوابة parity 163/163 تفرض انسجام زوج التصدير.

## نسخ/ترحيل الخدمة

بما أن الخدمة واحدة عديمة الحالة (حالة قاعدة البيانات فقط): النقل إلى
مزود آخر = نفس المعادلة (بناء `npm ci --include=dev && npm run build`
مع `DATABASE_URL`، ثم `npm start`) + ضبط `TZ=UTC`. المتغيرات الثلاثة
الإلزامية موثقة في [06-configuration](06-configuration.md).
