# 14 — استكشاف الأخطاء وإصلاحها

> تصنيف كل بند: **[مؤكد]** رُصد فعليًا في هذا المستودع (تاريخه/بواباته)،
> أو **[احتمالي]** تشخيص عام بنيته البنية. لا تدّعي إصلاحًا دون إعادة
> تشغيل الفحص المعني.

## الإقلاع والتكوين

| العرض | السبب المحتمل | الحل |
|---|---|---|
| الخلفية تموت فورًا برسالة env | متغير إلزامي ناقص (`DATABASE_URL` أو سرّا JWT) — فشل مبكر في `env.ts` **[مؤكد سلوك]** | أكمل `backend/.env` من `.env.example`؛ راجع [06](06-configuration.md) |
| تحذير «سرّا JWT متطابقان» عند الإقلاع | ضبط `JWT_ACCESS_SECRET=JWT_REFRESH_SECRET` **[مؤكد: seatbelt في index.ts]** | ولّد سلسلتين مختلفتين (`randomBytes(64).toString('hex')`) |
| `prisma migrate` يفشل على Neon | قاعدة نائمة أو استخدام pooler للترحيل | استخدم `migrate-deploy.mjs` (يبني direct تلقائيًا ويوقظ القاعدة 8×5s)؛ محليًا أعد المحاولة بعد ثوانٍ **[مؤكد: مصمم لهذا]** |
| `P1001/P1017` عابرة وقت التشغيل | انقطاع Neon لحظي | إعادة محاولة واحدة مدمجة في `db.ts`؛ إن تكررت افحص حالة Neon |
| تحذير أثناء `npm install` عن NODE_ENV=production | devDeps ستُتخطى | شغّل بلا `NODE_ENV=production`، أو `npm ci --include=dev` (ما يفعله Render) **[مؤكد: warn-node-env.mjs]** |

## التطوير المحلي

| العرض | السبب المحتمل | الحل |
|---|---|---|
| `EADDRINUSE :4000/:5173` | عملية قديمة عالقة | أغلق العملية (أو غيّر `PORT`) |
| الواجهة 404 على API | خلفية غير مشغلة / proxy لا يمر | شغّل `npm run dev`؛ تأكد من 5173→4000 عبر `vite.config.ts` |
| اختبارات تعطي نتائج تواريخ غريبة | منطقة زمنية محلية | الأوامر الرسمية تثبت `TZ=UTC` (frontend scripts) — استخدم `npm test` لا vitest مباشرة |
| أرقام، لقطات، أو تنسيق مختلف عن الوثائق | وثيقة متأخرة عن الشيفرة | الشيفرة هي المصدر — صحّح الوثيقة في نفس الـPR (قاعدة AGENTS.md) |

## الإنتاج (Render)

| العرض | السبب المحتمل | الحل |
|---|---|---|
| `/health` يرد 503 `DB_UNAVAILABLE` | Neon بارد/مشكلة اتصال | البوابة تمتص 5 ثوانٍ؛ إن استمرت افحص `DATABASE_URL` و`sslmode=require` |
| بيانات مرفوعة اختفت بعد نشر | قرص Render زائل **[مؤكد: موثق في render.yaml]** | لا شيء يُكتب قرصًا اليوم عمدًا؛ ميزات رفع قادمة تتطلب disk/S3 أولًا |
| نشر نجح والموقع قديم | SW/كاش متصفح | `index.html` يُخدم no-cache عمدًا؛ أجبر تحديثًا صارمًا، وتحقق من `BUILD_ID` عبر `/health` |
| 429 مصادقة متكرر | حزمة auth 10/15د وصلت (اختبارات حمل مثلاً) | انتظر النافذة؛ `skipSuccessfulRequests` يعني النجاح لا يحتسب |

## فشل بوابات CI — خريطة سريعة

| الوظيفة | ماذا تفحص | أول شيء تنظر إليه |
|---|---|---|
| `lint` | ESLint (أخطاء فقط) | رفض الملف المذكور؛ التحذيرات الـ18 معروفة |
| `typecheck` | tsc + validate:colleges | خطأ النوع المذكور / ملف كلية |
| `build` | بناء الجهتين بلا DB | لا تستدعِ `npm run build` الجذري في بيئة بلا DB |
| `test-frontend/backend` | vitest | سجلات pino الحمراء في الخلفية **طبيعية** — انظر الحكم النهائي فقط |
| `design-gates` | icons + motion + **csp-hash** + parity | البوابة الرافضة تطبع البند والقيمة المتوقعة |
| `surface-drift` | انزياح الأسطح | حاليًا يتجاوز بلا لقطات (تجاوز صادق موثق) |

## إذا لم تحسم المشكلة

1. أعد إنتاج أصغر أمر فاشل محليًا بنفس الطريقة الرسمية (انظر
   [11-testing](11-testing.md)).
2. ابحث في سجل الالتزامات (`git log --oneline`) عن آخر من لمس الملف —
   رسائل rNNN تفصيلية عمدًا.
3. راجع [16](16-decisions-and-limitations.md) — ربما القيد معلن ومقصود.
