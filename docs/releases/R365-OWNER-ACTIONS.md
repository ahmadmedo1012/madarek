# R365 — إجراءات المالك المطلوبة (خارج المستودع)

كل ما في هذه القائمة يحتاج صلاحية أو حسابًا أو DNS أو دفعًا **لا يملكه المستودع**.
لم تُنفَّذ أي منها هنا، ولم يُدَّعَ نجاحها. ما أُنجز داخل المستودع موثّق في
`R365-CLOSEOUT.md`، فلا تعده.

> القاعدة الحاكمة: لا تُعِد كتابة إصلاحات E365/R364 الجاهزة. الترويسات الأمنية
> ومعرّف الطلب وفحص الخدمة الحيّة ومسبار السوك كلها حيّة وناجحة الآن.

## 1 · P0 — مراقبة الأخطاء الخارجية (يمنع الإطلاق غير المشروط)

**المشكلة:** أخطاء 500 تُسجَّل فقط في `OperationalAlert` وتُقرأ من لوحة المالك.
توجد 4 تنبيهات غير محلولة (آخرها 2026-11-14)، ولا يوجد أي مزوّد تتبّع أخطاء في الشجرة.

**الخطوات:**
1. أنشئ مشروعًا في مزوّد تتبّع (Sentry أو ما يعادله) واحصل على DSN واحد للخلفية.
2. أضف المتغيّر `SENTRY_DSN` في Vercel → Project → Environment Variables (Production + Preview).
3. **مطلوب تغيير كود** لتوصيل DSN: لا تكامل قائم اليوم. افتح مهمة صغيرة لإضافة
   `@sentry/node` في `backend/src/server.ts` و`errorHandler.ts` (اعتراض 5xx مع
   `requestId` الموجود أصلًا)، مع اختبار يثبت أن الخطأ يصل إلى المزوّد.
4. حتى يصل الكود: أبقِ تنبيهات `OperationalAlert` تحت المراجعة اليومية، فهي القناة الوحيدة.
5. معيار الإغلاق: خطأ 500 مُصطنع في Preview يظهر في لوحة المزوّد خلال دقيقة.

## 2 · P1 — بريد Resend (مانع إطلاق)

**الحالة المقيسة الآن:** 118 رسالة فاشلة (قائمة ميتة)، 36 في الانتظار، واحدة عالقة في
`sending`، و4 مُرسلة فقط. `MAIL_FROM` ما زال مرسل Resend التجريبي المشترك، والمفتاح
المُعطى للقراءة مرفوض (`restricted_api_key`) فلا يمكن التحقق من النطاق آليًا.

**الخطوات:**
1. في لوحة Resend: أضف النطاق (مثل `madarek.ly`) وطبّق سجلات DNS التي يعرضها
   (SPF + DKIM، وDMARC إن طُلب) حتى تصبح الحالة **Verified**.
2. حدّث المتغيّرات في Vercel Production:
   - `MAIL_PROVIDER=resend`
   - `MAIL_FROM=مدارك <no-reply@<النطاق-الموثّق>>`
   - `MAIL_REPLY_TO` (اختياري لكن مُستحسن)
3. أعد النشر (Redeploy) حتى يُقرأ المتغيّر الجديد.
4. اختبر بريدًا واحدًا إلى عنوان تملكه فعلًا — لا ترسل اختبارًا إلى مستخدم حقيقي.
5. بعد نجاح الاختبار فقط، فرّغ القائمة الميتة عبر واجهة بريد المالك:
   `GET /api/v1/admin/mail/outbox?status=failed` ثم
   `POST /api/v1/admin/mail/outbox/{id}/retry` لكل رسالة (أو أعد تشغيلها بعد إصلاح
   المرسل). الرسالة العالقة في `sending` تُلغى ثم تُعاد بنفس الواجهة.
6. راقب أن `status=sent` يتزايد وأن `failed` لا يتزايد.

## 3 · P1 — نسخ احتياطي مجدول خارج الموقع + استعادة مُثبتة

**الحالة المقيسة:** لا يوجد workflow نسخ احتياطي. الأدوات موجودة:
`npm run db:backup` و`npm run db:restore` (و`db:verify`)، لكنها لا ترفع شيئًا عمدًا.
**تحذير:** المستودع عام؛ لا ترفع أي `.dump` إلى GitHub Artifacts أو Releases — سيصبح
بيانات الإنتاج (بما فيها تجزئات كلمات المرور) متاحًا للجميع.

**الخطوات:**
1. أنشئ حاوية **خاصة** (S3 أو Cloudflare R2) بحساب واحد فقط للنسخ، مع عمر افتراضي
   للكائنات (30–90 يومًا) وسياسة احتفاظ.
2. أضف أسرار المستودع: `BACKUP_S3_ENDPOINT`، `BACKUP_S3_BUCKET`،
   `BACKUP_S3_ACCESS_KEY_ID`، `BACKUP_S3_SECRET_ACCESS_KEY`، ثم مرجعية لسلسلة اتصال
   قراءة فقط (`PROD_DATABASE_URL` موجود أصلًا ويُستخدم في فحص الحسابات).
3. شغّل النسخة الأولى يدويًا وأثبت حجمها وبصمتها:
   `DATABASE_URL=… npm run db:backup -- --out backups/madarek-$(date -u +%Y%m%d).dump`
4. جرّب استعادة على قاعدة مؤقتة (لا على الإنتاج):
   `STAGE_DIRECT='postgresql://…' npm run db:restore -- --url-env STAGE_DIRECT --file <dump>`
   ثم قارن عدد الصفوف وجدول الترحيلات كما في `docs/12-deployment.md §3`.
5. جدول النسخ: Vercel Hobby لا يسمح بجدولة متعددة؛ استخدم مجدولًا خارجيًا (نفس البند 5)
   أو خطة مدفوعة. سجّل النتيجة (التاريخ/الحجم/بصمة SHA-256/زمن الاستعادة) في
   `docs/releases/`.

## 4 · P1 — خادم الاحتياط Render: قرار صريح قبل 2026-11-28

**الحالة المقيسة:** `https://madarek.onrender.com` يرد **503** الآن، و`render.yaml`
ما زال يعلن `autoDeploy: true` و`MADAREK_TEST_ACCOUNTS: '1'`.

اختر واحدًا واكتب القرار في سجل الإصدار:

* **إيقاف نهائي (الموصى به إذا كان Vercel + Neon كافيين):** أوقف الخدمة/احذفها من
  Render، وأزل `render.yaml` أو ضع في أوله سطر «RETIRED — ليس مصدر إنتاج» حتى لا
  يعيد أحد تفعيلها بالخطأ. أبقِ نسخة النشر في `gh-pages` كما هي.
* **تجديد:** ارفع الخطة، أعد النشر، ثم أصلح `render.yaml` (أزل
  `MADAREK_TEST_ACCOUNTS` أو اجعله `'0'`) وأعد فحص `/api/v1/health` وتأكد أن
  `buildId` يطابق `main`.

## 5 · P1/P2 — إيقاع المراقبة (GitHub cron)

**الحالة المقيسة:** `tick.yml` مجدول كل 5 دقائق لكنه أنتج 11 تشغيلًا في ~2.5 يوم
(≈4.4/يوم، أطول فجوة ~9 ساعات). `soak.yml` كل 15 دقيقة أنتج 4 تشغيلات في 4 أيام.
هذا تقييد منصة GitHub للمستودعات العامة، لا خطأ في المستودع.

**الخطوات (اختر واحدًا):**
1. **مجدول خارجي (الموصى به):** خدمة مجانية مثل cron-job.org أو EasyCron تنادي
   `POST https://madarek-app.vercel.app/api/v1/internal/tick` مع
   `Authorization: Bearer $CRON_SECRET` كل 5–15 دقيقة، و
   `GET /api/v1/health` كل 5 دقائق من موقعين. `CRON_SECRET` موجود في Vercel بالفعل.
2. **قبول مكتوب للوتيرة:** سجّل في `docs/HOSTING.md` أن الفحص اليومي كافٍ للمرحلة
   التجريبية، وأن فجوة 9 ساعات مقبولة، مع مسؤولية مراجعة يومية.

في الحالتين: لا تحوّل `soak` إلى بوابة إلزامية على `main` — هي مسبار حيّ لا اختبار كود.

## 6 · P2 — انحراف البيانات التجريبية (`MADAREK_TEST_ACCOUNTS`)

الحساب التجريبي `student@test.ly` نشط في معهدين (`ulara-demo` و`madarek-demo`)، وهذا
صحيح من ناحية المنتج (قاعدة fail-closed من r349) لكنه يُظهر شاشة اختيار المعهد.

**القرار المطلوب:** هل تريد حسابات `@test.ly` حيّة في الإنتاج؟
* **نعم (عروض/فحوص):** أبقِ `MADAREK_TEST_ACCOUNTS=1` ووثّق أن الحساب التجريبي
  متعدد المعاهد. لا تحذف صفوف العضوية — الحذف تغيير إنتاجي غير مصرّح به هنا.
* **لا:** أزل `MADAREK_TEST_ACCOUNTS` من Vercel Production (وأزل `'1'` من
  `render.yaml`)، ثم أعد النشر. الحسابات تبقى، لكنها لن تُعاد تهيئتها عند كل إقلاع.

## 7 · أمني عاجل — تدوير المفاتيح

المفاتيح التي أُرسلت في المحادثة (GitHub PAT، Neon، Resend، Vercel، Expo) ومفتاح
GitHub الذي كان مضمّنًا في `.git/config` محليًا **صارت مكشوفة**. أبطِلها وأنشئ بدائل:

1. GitHub → Settings → Developer settings → Personal access tokens: revoke ثم أنشئ بديلًا.
2. Neon → Reset password لمستخدم `neondb_owner` (ثم حدّث `DATABASE_URL` في Vercel).
3. Resend → أبطِل المفتاح وأنشئ مفتاحًا كاملًا (لا للقراءة فقط) بعد توثيق النطاق.
4. Vercel → Tokens: revoke.
5. Expo → Access tokens: revoke.
6. تحقّق أن لا مفتاح في تاريخ Git:
   `git log -p -S'ghp_' --all -- . | head` (يجب أن لا يظهر شيء في الملفات المتتبَّعة).
