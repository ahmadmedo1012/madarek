# GRAPHICS-PIPELINE — Madarek's visual construction system (R366 L2, Agent 1)

The one document that decides how every Madarek visual is built, shipped and
verified. Source of truth for the numbers: the frozen Heron specs
(`docs/redesign/r335/heron-spec/`), the live re-measure
(`docs/redesign/r366/agent1-heron/evidence/l1-reference-remeasure/`), and the
budget table in `docs/redesign/r366/agent1-heron/evidence/l2-asset-budget.md`.

## 1. How the reference builds its visuals (measured, not guessed)

From the frozen census (all 5 breakpoints, re-confirmed live 2026-11-17 — the
live tree is byte-identical in element count: 320 hero elements, 0 only-live,
0 only-frozen):

- **The hero plate** is a *technical plate*: one full-bleed raster (the ink
  elevation, 1373×647 @1440) + furniture — 1px hairline ruler overlays (two
  clipped sets tracking the drawing), four 10px corner bracket svgs, a frame
  edge (7px strips), two 12px map pins with two-line white labels, one
  130×35 ink tag, one 8px ember crosshair. **At rest the furniture is quiet:
  86 seats at opacity .64, 14 at opacity 0** (the pins, the tag, the crosshair
  label) — the reveal is scroll choreography. This is why the live page reads
  as "a line drawing over paper" — the calm is literal, measured, and ours to
  reproduce exactly (we do: `HeroPlate`, conformance-bound).
- **Section art** (journey, why, roles, problems) are pre-rendered rasters
  (webp on the reference; PNG-derived), each with light/dark variants, inset
  into ruled layouts — no WebGL anywhere, no video loops, no sprite sheets.
- **Motion** is GSAP tweens (setup + scroll-scrubbed); the census records the
  table (`_motion.*.json`). Our equivalent is CSS transitions + scrub vars
  (`--wr-p`, `--wy-p`, `--cf-p`, `--cr-p`) — no GSAP in our stack (the r331
  port decision).

## 3. The decision matrix (measured numbers, per visual class)

**(a) Procedural SVG + CSS (zero deps)** — chosen for: the hero furniture,
the plate language (rulers/brackets/pins), app illustrations, interactive
constructs. Numbers: the hero furniture = 169 DOM seats, ~9 KB gz of CSS +
~2 KB gz of JSX (inside the landing bundle — within the +2 KB entry law);
crisp at every DPR; theme-flip by token cascade; `prefers-reduced-motion`
collapses to the static sheet. This is the DEFAULT for anything that draws
with lines, type and flat fills.

**(b) Pre-rendered rasters (webp ≤ 60 KB, AVIF when the resolution demands)** —
chosen for: photographic-density art (the courtyard, the campus, the role
captures, the journey scenes, the skyline). Numbers (measured @ this round):
every r342 asset now ≤ 60 KB (the diet: statement-courtyard 228→57 KB,
problems 98–166→57–61 KB, roles 72–175→59–61 KB, journey 64–109→46–61 KB,
skyline@2x 119→59 KB; the dead hero-campus@2x retina twins deleted, −650 KB;
total 3.1 MB→2.4 MB). Encode recipe (ffmpeg, this repo's tool):
`ffmpeg -i in.webp -vf scale=W:-2 -c:v libwebp -quality Q out.webp`
(Q descends 70→35, then scale 0.85× steps; quality floor 35 for line art).
When a required resolution cannot hit 60 KB in webp (e.g. 1200² line art
bottoms at ~118 KB @q30), **AVIF** is the escape:
`ffmpeg -i in -c:v libaom-av1 -crf 46 -cpu-used 8 -still-picture 1 -tiles 2x2`
— measured 0.6 s/file, 1200² → 63 KB (−72 % vs the webp source). Ship as a
`<picture>` twin with the webp fallback (the r307 media pins keep passing —
the `src` attribute is the pinned string). *Not used today because the diet
reached budget in webp; the recipe is the standing rule for the next asset
that can't.*

**(c) Lazy WebGL (`three` + Draco/meshopt glTF)** — **rejected for the
public site** with numbers: the entry has ~0.4 KB slack against the 774 KB
gate; a three-based hero scene is 150–600 KB gz even compressed (≈ the whole
current landing CSS); LCP on mobile 4G would need the scene to be
below-the-fold-lazy, which the hero by definition is not; the reference
itself ships zero WebGL (measured). WebGL remains available for the
authenticated app's future 3D constructs (Agent 4's surface), where a lazy
chunk ≤ 120 KB gz + `IntersectionObserver` gating is the law — never for the
public landing.

## 4. The construction rules (one system — the plate language)

1. **Projection**: orthographic elevations/plans (the drafting-table
   metaphor) — no perspective grids on the plate; camera-free by design.
2. **Light**: single ambient + one ember accent; light direction
   top-inline-start, consistent across every visual; dark mode inverts the
   paper/ink pair (tokens flip, geometry never moves).
3. **Colour temperature**: paper `#F6F6EE` / ink `#282828` / soft ink
   `rgba(40,40,40,.72)` / hairline `rgb(224,224,218)` / ember `#FA3600`
   (`--accent` — the token IS the measured value). No second accent, no
   gradients on the plate.
4. **Materials**: paper (the page itself), ink (line art, 1px at rest),
   ember (interaction/state only). The hairlines sit at opacity .64 at rest
   (the measured census seat).
5. **Edge/hairline weights**: 1px rules (0.12rem on the fluid root), 7px
   frame strips, 10px corner brackets, 12px pins — the measured furniture
   seats; the loud chrome (dashes, ± marks, graticule, deco cards) stays
   retired (R347 D4).
6. **Grid/ruler annotations**: every measured plate may carry ruler
   hairlines + mono gutter indices (`[nn]`, `PLATE K-102`) — always at the
   census's own calm register.
7. **RTL mirroring**: annotations mirror; the ink art is authored per
   component (mirrored paths); numerals/Latin runs ride `dir="ltr"` spans.
8. **Safe areas**: every visual seats inside the sheet frame (7px inset,
   8px gutters @390 — measured); nothing under the in-flow masthead zone.
9. **Accessibility**: decorative art `aria-hidden`; informative art gets
   `role="img"` + Arabic alt (the r342 manifest carries `altAr`); no
   information exists only inside a graphic.
10. **Performance laws**: DPR-capped rasters (≤2x twins, referenced or
    deleted — dead retina is deleted, not accumulated); off-screen media
    lazy (`loading="lazy"`, except the one LCP candidate which carries
    `fetchpriority="high"`); `width`/`height` (or aspect-ratio) on every
    img (CLS ≤ 0.05); `prefers-reduced-motion` collapses the reveal
    choreography; `Save-Data`/low-end devices get the same stills (the
    furniture is DOM, not media).

## 5. Verification (the gate)

`node scripts/graphics/verify-graphics.mjs` — enforces the 60 KB budget, the
light/dark twin pairing, the naming register, ffprobe-parseable dimensions,
the @2x aspect match and the no-dead-retina law. Exit 1 on violation; run it
in every PR that touches `public/media/**` or `components/illustrations/**`.

Current state: **PASS — 56 raster assets, 2,471 KB total, every file ≤ 60 KB.**

## 6. Mobile consumption note (cross-agent)

`apps/mobile/src/media/illustrations.generated.ts` consumes the same
`public/media/illustrations/**` files by URL. The r342 diet changed byte
sizes and some pixel widths (aspect ratios unchanged — the mobile layout
metadata stays valid). Expo does not guarantee AVIF decode on older devices,
so the mobile-shared set stays webp (the AVIF escape is web-only `<picture>`
twins). See `docs/redesign/r366/REQUESTS-agent1-to-agent5.md`.
