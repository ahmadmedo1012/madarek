# قائمة خطوات Firebase — الدفع الحقيقي لتطبيق أندرويد (خطوة المالك الوحيدة المتبقية)

> هذه الصفحة هي **الإجراء الوحيد المطلوب منك** لتشغيل الإشعارات الفورية على أندرويد.
> كل ما عداها جاهز في المنصة. الملف مرجع أيضًا في `docs/HOSTING.md`.
> الوقت المتوقع: **15–20 دقيقة**. بعدها أرسل الملفات للمطوّر وسيتولى الباقي.

## لماذا هذه الخطوة؟ (الحالة الموثّقة اليوم)

فحص R353/R354 أثبت أن كل شيء يعمل **إلا** مفتاح FCM:

- ✅ كود التطبيق جاهز: تسجيل التوكن، مركز الإشعارات، الشارة، السكوت الليلي، تقليم الرموز الميتة.
- ✅ الخادم جاهز: `PUSH_ENABLED=true` (افتراضيًا منذ R354)، الإرسال عبر Expo push، الإيصالات، مفاتيح الدمج.
- ❌ مشروع Expo **لا يحمل بيانات FCM v1** (`androidFcm: null` — تحقّق R353 عبر Expo API).
- ❌ لا يوجد `google-services.json` في المستودع (قانون المستودع: لا أسرار فيه).

بدون هذه الخطوة لا يستطيع الجهاز الحصول على توكن FCM أصلًا، فلا يمكن لأي إشعار الوصول.

## الخطوات (console.firebase.google.com)

### 1. أنشئ مشروع Firebase (3 دقائق)
1. افتح [console.firebase.google.com](https://console.firebase.google.com) → **Add project**.
2. الاسم المقترح: `madarek`. لا تحتاج Google Analytics (فعّله أو لا — لا يهم).
3. من إعدادات المشروع → **Project settings → General** → دوّن **Project ID**.

### 2. أضِف تطبيق أندرويد (دقيقتان)
1. في صفحة المشروع → أيقونة أندرويد (**Android app**) → **Add app**.
2. **Android package name** (مهم جدًا — انسخه حرفيًا): `ly.madarek.mobile`
3. App nickname: `مدارك`. شهادة التوقيع SHA-1: اختياري الآن (يُطلب لاحقًا لتوقيع المتجر فقط).
4. اضغط **Register app** ثم **Download `google-services.json`**.

### 3. فعّل Cloud Messaging وولّد مفتاح الخدمة (5 دقائق)
1. القائمة اليسرى → **Engage → Cloud Messaging** (أو البحث عن Messaging).
2. إذا ظهر خيار **Firebase Cloud Messaging API (V1)** — تأكد أنه **Enabled** (في معظم المشاريع الجديدة مفعّل تلقائيًا؛ إن ظهر "Enable" اضغطه).
3. **Project settings → Service accounts** → **Generate new private key** → **Generate** → ينزّل ملف JSON (اسمه مثل `madarek-firebase-adminsdk-xxxxx.json`). هذا هو **مفتاح FCM v1**.

### 4. أرسل الملفين للمطوّر (دقيقة)
أرسل عبر قناة آمنة (واتساب/تيليجرام مباشرة أو أي وسيلة تفضلها):
1. `google-services.json` (الخطوة 2)
2. ملف الـ service account JSON (الخطوة 3)

> لن يُرفع أي منهما إلى GitHub أبدًا — يُحمَّلان إلى Expo/EAS كأسرار.

## ما سيقوم به المطوّر بعد استلام الملفات (حتى تعرف ما ينتظرك)

1. إضافة `googleServicesFile` إلى إعدادات بناء التطبيق + رفع مفتاح FCM v1 إلى EAS (Expo credentials).
2. إعادة بناء `android-latest` APK.
3. إرسال إشعار تجريبي على محاكي Google Play وتوثيق وصوله (Expo receipt `ok` + logcat).
4. تحديث هذا الملف إلى ✅ «مكتمل» في `docs/HOSTING.md`.

## أسئلة متكررة

- **هل هذا يكلف مالًا؟** لا — خطة Firebase المجانية تكفي (الإشعارات مجانية بلا حد عملي للاستخدام الحالي).
- **و iOS؟** إشعارات iOS تحتاج حساب Apple Developer مدفوع ($99/سنة) — مستقلة تمامًا عن هذه القائمة، والتطبيق يعرض «قريبًا» حتى قرارك.
- **هل أستطيع التراجع؟** نعم — حذف المشروع من Firebase يوقف كل شيء، والتطبيق يعود تلقائيًا إلى مركز الإشعارات الداخلي (يعمل الآن بلا Firebase).
