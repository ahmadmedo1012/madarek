# Visual identity layer: glassmorphism, particles, audio cues, accent theming

This change adds a 734-line CSS enhancement layer (`global-icon.css`) providing glassmorphism, particle effects, deep tinted shadows, border-shimmer hover effects, Oasis widget glow rings, morphing blob animations, and subtle gradient overlays. On the interactive side, it introduces a Web Audio API hook for click/success/notification sounds, a Zustand-persisted accent color picker with 6 presets that inject CSS custom properties at runtime, dark mode refinements (vignette, gradient overlays, card inner glow), and three section-specific skeleton components. A prior task's code (OasisWidget, DashboardCustomizer, i18n, code splitting, GlobalSearch) ships in the same diff.

**Watch for:** `will-change` on always-animating pseudo-elements causes permanent compositor layers on low-end devices (confirmed); AudioContext created eagerly on first store access rather than on user gesture, risking browser auto-play policy warnings (confirmed); `@property` registration needed for `--progress-angle` animation but absent, making the conic-gradient ring animation a no-op in most browsers (confirmed); accent color CSS vars overwrite design-token `--accent` globally, breaking any component that assumes `--accent` is the primary brand color (likely).

## High-level view

The glassmorphism CSS applies `backdrop-filter: blur()` to sidebar, Oasis panel, and customizer modal using undefined custom properties (`--glass-blur`, `--glass-bg`, `--glass-border`). If these tokens aren't defined in the existing cascade, every glassmorphism rule becomes inert or worse — the sidebar loses its visible background.

The particle system animates pseudo-elements with `will-change: transform, opacity` on infinite loops. Because these are always-on (not triggered by interaction), the browser promotes these layers permanently, increasing GPU memory on every page that carries the `.particles-bg` or `.landing-hero` class.

The audio cue hook creates a single shared `AudioContext` on first use. If the first `playClick` call happens before a user gesture, Chrome and Safari will suppress audio silently. The current try/catch prevents crashes but the first sound may be lost.

The accent color system injects values into `--accent` on `document.documentElement.style`. The particle CSS and shadow CSS both reference `var(--accent)` for tinting. When the user selects "rose" or "amber", all particle dots, shadow tints, and gradient overlays shift color — tight coupling that may produce jarring results if not intentional.

The CSS `progress-ring` animation attempts to animate `--progress-angle` from `0deg` to a target. Without `@property` registration, the browser cannot interpolate the value and the ring appears fully drawn instantly with no animation.

1. **Undefined `--glass-blur` token** (confirmed) — `global-icon.css` references `var(--glass-blur)` but no fallback value is defined in this file or in the token imports. Add a fallback: `blur(var(--glass-blur, 12px))` or define the token in `tokens.css`.

3. **AudioContext created before user gesture** (confirmed) — `getAudioContext()` is called inside Zustand store actions. If any code path triggers `playClick` before a user interaction, Chrome suppresses audio silently. Add `ctx.resume()` inside `playTone` to recover from suspended state.
4. **Missing `@property` for `--progress-angle`** (confirmed) — The `gi-progress-ring-animate` keyframe animates a custom property, but CSS cannot interpolate custom properties without `@property { syntax: '<angle>'; ... }`. The animation is a no-op without it.

## Glassmorphism depending on phantom tokens

Section 1 of `global-icon.css` applies backdrop-filter blur and sets background/border using three custom properties:

```css
.sidebar {
  backdrop-filter: blur(var(--glass-blur));
  background: var(--glass-bg);
  border-inline-end: 1px solid var(--glass-border);
}
```

None of these properties are defined in the diff. If `--glass-blur` resolves to empty, `blur()` is invalid and the declaration is dropped. `background: var(--glass-bg)` with an undefined property resolves to `initial` (transparent), meaning the sidebar loses its visible background. Adding inline fallbacks (`var(--glass-blur, 12px)`, `var(--glass-bg, rgba(255,255,255,0.8))`, `var(--glass-border, rgba(255,255,255,0.2))`) makes the system resilient.

## Particle pseudo-elements and GPU memory

```css
.particles-bg::before {
  animation: gi-particle-float 8s var(--ease-soft) infinite;
  will-change: transform, opacity;
}
```

`will-change` on elements with infinite animations is redundant — the browser promotes during animation anyway — but prevents the layer from being reclaimed when the element scrolls off-screen. On pages where `.particles-bg` is applied to the dashboard container, this means two permanent GPU layers for purely decorative particles. On mobile devices with limited GPU memory, this contributes to frame drops. Removing `will-change` lets the browser manage promotion adaptively.

## AudioContext lifecycle gap

```ts
let audioCtx: AudioContext | null = null;

function getAudioContext(): AudioContext | null {
  if (!audioCtx) {
    audioCtx = new AudioContext();
  }
  return audioCtx;
}
```

If `playClick` fires before a user gesture (possible via effects or store subscriptions on mount), `AudioContext` starts in "suspended" state. The try/catch silences errors but the oscillator produces no sound. Adding a `ctx.resume()` call at the top of `playTone` fixes this — the browser will automatically fulfill the resume promise on the next user-initiated event:

```ts
if (ctx.state === 'suspended') ctx.resume();
```

## Custom property animation without @property

```css
@keyframes gi-progress-ring-animate {
  from { --progress-angle: 0deg; }
  to { --progress-angle: var(--target-angle, 270deg); }
}
```

CSS cannot interpolate custom properties without `@property` registration. Without it, the browser treats the value change as discrete (instant flip), so the conic-gradient ring shows its final state immediately with no sweep animation. The fix:

```css
@property --progress-angle {
  syntax: '<angle>';
  inherits: false;
  initial-value: 0deg;
}
```

## Accent color namespace collision

`useAccentColor.ts` calls `root.setProperty('--accent', values.accent)`. The entire `global-icon.css` particle system, shadow system, and gradient system reference `var(--accent)` to tint effects. Switching accent to "rose" (#fda4af) turns every particle dot, shadow tint, and card gradient pink. If this is intentional (full-app adaptive theming), it works. If components elsewhere assume `--accent` is the static brand blue, they'll shift unexpectedly. Namespacing (`--user-accent`) and having the decoration layer explicitly reference the user-chosen variable would decouple these concerns.
