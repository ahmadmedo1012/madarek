# World-class visual platform upgrade: i18n, animations, AI widget, and code splitting

This change adds nine features in a single sweep: a custom i18n system (Zustand store with ar/en dictionaries, LangToggle component, document dir/lang sync), a 1170-line micro-interactions CSS file, a floating "Oasis" AI chat widget, enhanced global search (suggestion chips, recent searches, category filters), dashboard widget customization (visibility/ordering persisted to localStorage), a gamification widget (XP counter, level ring, mini leaderboard), five inline SVG illustration components, virtual lab card hover interactions, and React.lazy code splitting for all page routes.

The approach is purely additive: new stores, new components, new CSS, and a refactored App.tsx that wraps existing routes in Suspense boundaries. No backend changes; everything runs client-side with data from existing hooks.

**Watch for:** Oasis widget conversation state leaks memory across the session (confirmed); the `t()` function uses stale closures in concurrent renders (likely); the i18n system does not translate page titles in the Topbar/AppShell PAGE_TITLES map (confirmed); code splitting duplicates module loads for named-export pages (confirmed).

## High-level view

The i18n system provides translation for new widget text but doesn't reach the existing PAGE_TITLES dictionary in AppShell, leaving the topbar hardcoded in Arabic. The `t()` selector returned by the Zustand store is referentially stable across locale changes, meaning memoized children that receive it as a prop won't re-render when the user switches language.

The Oasis widget accumulates messages in local state without any cleanup or cap, so a long session will grow an unbounded array. Its two close buttons (Minimize2 and X) both call the same `closeOasis` action, making the minimize button a visual duplicate rather than a distinct behavior.

Code splitting converts every page to `React.lazy`, including multiple named exports from the same module (e.g., nine components from `MorePages.tsx`). There's no error boundary wrapping the Suspense, so a failed chunk load crashes the entire app rather than showing a retry UI.

Dashboard customization only covers the five hardcoded widget IDs. There's no migration or version key on the persisted localStorage data, so widget ID changes across deploys may produce unexpected layouts.

The `runningIdx` mutable variable in GlobalSearch breaks React's render purity contract and will produce incorrect keyboard navigation indices under StrictMode double-render.

## i18n store and the PAGE_TITLES gap

AppShell's `PAGE_TITLES` record and `resolveTitle()` function remain hardcoded Arabic strings. When the user switches to English, the topbar title stays Arabic. The i18n store already has keys like `nav.dashboard`, `nav.courses`, etc. that map to these titles, but nothing in AppShell reads them. The i18n system works for the new widgets but doesn't reach the most visible text on every page.

The `t()` function:

```ts
t: (key: string) => {
  const state = get();
  return state.dictionaries[state.locale][key] ?? key;
}
```

It calls `get()` (Zustand's live state getter) so it always reads the current locale at call time. The risk: if a component destructures `const { t } = useTranslation()` and passes `t` as a prop to a `React.memo` child, that child won't re-render when locale changes because `t` is referentially stable (same function identity). The child's displayed text updates only when it re-renders for other reasons — a latent inconsistency on locale switch.

## Oasis widget memory accumulation

`OasisWidget` stores messages in `useState<ChatMsg[]>([])` with no upper bound. The component lives in AppShell, so it persists across all page navigations. A user who actively chats will accumulate hundreds of messages in memory. The auto-scroll `useEffect` runs on every message change, computing layout on a growing DOM node list.

The `conversationId` state means the backend tracks context, so old messages can't be discarded from the API's perspective. But the rendered DOM should either be capped or virtualized to prevent degradation over a long session.

## Code splitting: missing error boundary and chunk duplication

The App.tsx refactor converts ~50 page imports to `React.lazy`. For named exports (`MorePages.tsx` exports 9 components, `TeacherPages.tsx` exports 8), each gets its own `React.lazy(() => import('...').then(m => ({ default: m.X })))` call.

The manual chunks configuration in `vite.config.ts` lists relative paths:

```ts
'pages-student': [
  './src/pages/student/DashboardPage',
  './src/pages/student/CoursesPage',
  ...
]
```

Manual chunks in Vite's `rollupOptions.output.manualChunks` expect resolved module IDs, which may not match these relative paths depending on Vite's resolution. If the grouping doesn't match, Rollup falls back to its own splitting heuristic, potentially producing more chunks than intended.

The Suspense boundary uses `<PageSkeleton />` as fallback but has no error boundary. A failed chunk load (network error, CDN outage) crashes the app to React's unhandled error state rather than showing a retry UI. This is a production reliability gap.

## Dashboard customization: fragile reorder contract

The reorder logic:
```ts
reorderWidgets: (ids: string[]) =>
  set((state) => ({
    widgets: state.widgets.map((w) => ({
      ...w,
      order: ids.indexOf(w.id),
    })),
  })),
```

If `ids` doesn't contain all widget IDs, `indexOf` returns -1, giving some widgets `order: -1` and pushing them to the top when sorted. The DashboardCustomizer always passes all IDs from the sorted array today, but this is a fragile contract — any future caller that passes a partial list will silently corrupt the ordering.

## GlobalSearch render purity violation

The `runningIdx` variable for keyboard navigation is declared with `let` at render scope and mutated during JSX mapping:

```tsx
let runningIdx = 0;
// ...inside JSX:
const idx = runningIdx++;
```

Under React StrictMode (which double-invokes render functions), `runningIdx` will be incremented twice, producing indices that don't match the actual DOM elements. This manifests as keyboard up/down highlighting the wrong item. A `useMemo` computing cumulative offsets per section would be idempotent across re-renders.
