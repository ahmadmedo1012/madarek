# Schedule/Results content fill and homepage animation polish

The change adds MetricCards to SchedulePage and a semester performance trend card to ResultsPage (reducing empty space), then appends ~130 lines of CSS to `visual-final-polish.css` covering homepage hover/entrance animations, a CTA pulse, staggered KPI entrance, and baseline text-readability overrides.

Watch for: The `landing-pilot-ring` rotation animation (confirmed) conflicts with the existing `ring-fill` reveal animation, producing visual breakage on the pilot stats. The broad `.card p` and `.page .text-sm` selectors risk overriding compact/flush card variants and inflating sidebar/nav text (likely).

## High-level view

The MorePages.tsx additions are type-safe, use existing primitives, and introduce no new dependencies.

The CSS animations section targets real class names in the landing page and dashboard. Most are simple hover lifts and entrance staggers with good easing. The exception is `landing-pilot-ring`: the new `ring-spin` infinite rotation overrides the existing conic-gradient progress rings that use `ring-fill` as a one-shot reveal, transforming percentage indicators into endlessly-spinning circles.

The "text clarity" CSS block re-declares `.page { gap }`, `.card { padding }`, and `.grid-N { gap }` identically to rules already present at lines 222–261 of the same file — copy-paste duplicates with no behavioral impact. The `.page p, .card p` minimum font-size rule forces `max(0.875rem, 14px)` on every paragraph inside any `.card`, including compact sidebar cards and notification panels where tighter text is intentional.

## Pilot ring rotation vs. progress semantics

The existing `landing-pilot-ring` elements are conic-gradient arcs sized by `--ring-deg` (e.g. 144deg for 40%). Their CSS in `redesign-landing.css` (line 502) sets `transform: translate(-50%, -50%)` for centering and uses a one-shot `ring-fill` animation on `.in-view` to scale them in. The new rule at line 1056 of `visual-final-polish.css`:

```css
.landing-pilot-ring {
  animation: ring-spin 8s linear infinite;
}
```

applies `rotate(0→360deg)` unconditionally. Because `visual-final-polish.css` loads last ("maximum cascade authority" per its own header), this wins. The rings will spin continuously, destroying the percentage visualization. The `ring-fill` animation from `.in-view` may still fire, but with both competing `animation` properties the behavior is browser-dependent — at best the ring spins, at worst it flickers between states.

Fix: remove the `ring-spin` rule entirely. If a decorative spin effect is desired, apply it to a separate pseudo-element or a dedicated decorative class, not the data-bearing ring.

## Overly-broad text-size floor

```css
.page p, .card p, .page-subtitle, .page .text-sm {
  font-size: max(0.875rem, 14px);
  line-height: 1.6;
}
```

`.card p` matches every paragraph in every card on the platform. The `.card.compact` and `.card.flush` variants are designed for dense content (notification panels, sidebar widgets, table headers). This rule forces them to 14px/1.6, overriding the intentional 11–12px sizing from `--fs-xxs` / `--fs-xs`.

Similarly, `.page .text-sm` overrides utility-class sizing for any `.text-sm` element inside `.page`, which is the entire app content area. The specificity is equal to the utility definition (`.text-sm { font-size: var(--fs-sm) }` in utilities.css) but wins by source order since visual-final-polish loads later.

Scope the readability floor to content sections: `.page > .card:not(.compact):not(.flush) p` or add a dedicated `.readable` class.
