# Premium Visual Rebuild: Homepage, Dashboard, Lecture Player, Matrix, and Global Design System

A comprehensive CSS-forward visual elevation of four key pages (LandingPage, Student Dashboard, Lecture Player, Learning Path Matrix) plus a global design system unification layer. The approach adds ~2500 lines of CSS across six new stylesheets and ~500 lines of TSX changes, keeping all existing functionality intact while layering premium visual treatments on top. The strategy is additive: new `redesign-*.css` files load after the existing stylesheets and override via specificity, avoiding destructive edits to the base design system.

**Watch for:** CSS specificity conflicts from heavy `!important` usage across the redesign layers that will make future overrides painful (confirmed). A hidden Doughnut chart kept for "chart.js compatibility" that still renders and costs bundle weight (likely). The `--fs-base` bump from 14px to 15px is a global change that affects every unsized element on the platform (confirmed). Duplicate bottom-nav active-dot declarations in both `responsive.css` and `stitch-canonical.css` (confirmed).

## High-level view

The homepage gains a floating 3D card showcase replacing the static photo, a gradient mesh hero background, a trust bar section, typing animation in the AI chat, conic-gradient stat rings for pilot results, and a premium CTA section with noise texture and floating shapes. One `import React` is added to enable `React.CSSProperties` type assertions for CSS custom properties passed via inline style.

The student dashboard introduces a CSS-only GPA gauge ring and progress ring that visually replace the Chart.js Doughnut — but the Doughnut is still rendered in a zero-size container, keeping chart.js in the critical path unnecessarily. New quick-actions, quick-stats, term milestones, and stagger agenda animations fill out the premium dashboard feel.

The lecture player and matrix pages get lighter TSX changes: floating progress bar, glassmorphism checkpoint overlay (missing scroll lock on iOS), meta bar stubs, and per-cell CSS progress fills in the matrix driven by `--cell-level` custom properties.

The global layer (redesign-global.css) applies card elevation tiers, button hover shimmer, scrollbar branding, and branded text selection. tokens.css shifts dark surfaces warmer and bumps `--fs-base` to 15px, collapsing the `--fs-base`/`--fs-md` type scale step.

<summary>Issues (7)</summary>

1. **Hidden Doughnut still renders** — The Chart.js Doughnut inside DashboardPage is hidden with `width: 0; height: 0; overflow: hidden` but still initializes a canvas and registers with ChartJS. Remove the Doughnut entirely or lazy-load it behind a feature flag to eliminate the bundle cost and flash risk.
2. **Duplicate bottom-nav dot declarations** — Both `responsive.css` and `stitch-canonical.css` define `.bottom-nav-item.active::after` with competing animations and sizes (4px vs 5px, different keyframe names). Consolidate into one file to prevent cascade unpredictability.
3. **Excessive !important in redesign layers** — `redesign-landing.css` uses `!important` on transforms, masks, and opacity rules. This makes surgical overrides by future features very difficult. Prefer higher-specificity selectors (e.g., `.landing .landing-bento-wide::after`) instead of importance escalation.
4. **--fs-base 14px to 15px is globally breaking** — Every element that inherits `--fs-base` without an explicit size override will grow. Verify downstream that form inputs, table cells, badges, and compact UI still fit their containers on mobile.
5. **Mobile hero empty zone** — On screens < 640px, `.landing-hero-float-card` switches from `position: absolute` to `position: relative`, but the container retains `min-height: 240px` and `perspective: 900px`, leaving ~100px of dead vertical space below the single visible card.
6. **Checkpoint overlay scroll bleed on iOS** — `.checkpoint-glass` covers the viewport with `position: fixed` but there's no body scroll lock in the JSX. On iOS Safari, users can scroll the body behind the overlay.
7. **No build verification** — The environment couldn't run `tsc` or `vite build`. Structural checks (brace balance, import presence) passed, but type errors from `React.CSSProperties` casts on custom properties are unverified.

## Hidden chart.js Doughnut in DashboardPage

The new CSS-only progress ring replaces the Doughnut chart visually, but the original Doughnut component is still rendered inside a zero-size container:

```tsx
<div style={{ position: 'absolute', width: 0, height: 0, overflow: 'hidden' }}>
  <Doughnut ... />
</div>
```

`ChartJS.register(ArcElement, Tooltip, Legend)` still runs at module level, and the Doughnut still creates a canvas element and animation frames. If it's meant to prevent tree-shaking from removing chart.js for other pages, that's not how bundlers work — other pages importing chart.js keep it alive on their own. This is dead code that costs bundle size and a frame or two of paint on mount. (confirmed)

## Duplicate bottom-nav active indicators

`responsive.css` defines `.bottom-nav-item.active::after` with a `4px` dot and `bnav-dot-in` keyframe. `stitch-canonical.css` defines the same selector with a `5px` dot, different `box-shadow`, and `stitch-dot-pop` keyframe. In the current `main.tsx` import order:

```
responsive.css       (line 11)
stitch-canonical.css (line 18)
```

`stitch-canonical.css` wins by cascade order, making the `responsive.css` declaration dead code. Both include RTL keyframe overrides, adding noise. Any future re-ordering of CSS imports will silently break the visual. (confirmed)

## !important proliferation in redesign layers

```css
.landing-bento-wide::after {
  content: '' !important;
  position: absolute !important;
  opacity: 0.7 !important;
  -webkit-mask: none !important;
  mask: none !important;
}
.landing-bento-card:hover {
  transform: translateY(-6px) !important;
}
```

The `mask: none !important` overrides a mask set on the same pseudo-element in an earlier stylesheet. This creates an arms race: any future refinement must also use `!important` or restructure the cascade. A scoped selector (`.landing .landing-bento-wide::after`) or a single combined stylesheet would be more maintainable. (confirmed)

## Font size base bump collapses type scale

`tokens.css` changes `--fs-base` from `14px` to `15px`. Since `--fs-md` was already `15px`, these two tokens are now identical — collapsing a step in the type scale. Every element using `--fs-base` grows by 1px platform-wide. Admin tables, compact badges, and form labels were tuned for 14px and may overflow or feel loose on mobile. (confirmed)

## Mobile hero empty space

On screens below 640px, cards 2 and 3 are `display: none` and card 1 becomes `position: relative`. The container retains `min-height: 240px` (or `200px` at 480px) and `perspective: 900px`. With a single `max-width: 260px` card inside, this leaves 100–140px of dead vertical space and a meaningless perspective declaration. Remove or reduce `min-height` on phone and drop perspective when no 3D transforms are active. (confirmed)

## Checkpoint overlay scroll bleed

The `.checkpoint-glass` overlay is `position: fixed; inset: 0` with `backdrop-filter: blur(16px)`. The Sidebar uses `document.body.style.overflow = 'hidden'` in a `useEffect` for its drawer, but no equivalent lock exists when `activeCheckpoint` is set. On iOS Safari, users can scroll the page behind the fixed overlay by swiping, breaking the modal illusion. Add `overflow: hidden` to body (or use `overscroll-behavior: contain` on the overlay) when the checkpoint is active. (likely)

## Missing @keyframes avatar-ring-spin

`redesign-landing.css` references `animation: avatar-ring-spin 6s linear infinite` on `.landing-ai-avatar::before`, but no `@keyframes avatar-ring-spin` declaration appears in the diff. If this keyframe isn't defined in a pre-existing stylesheet, the animation silently fails and the conic-gradient ring remains static. (possible — verify by searching the full CSS bundle for `avatar-ring-spin`)
