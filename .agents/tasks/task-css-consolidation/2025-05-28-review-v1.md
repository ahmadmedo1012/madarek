# Consolidated CSS override layer and bottom-nav scroll-hide

A single `madarek-final.css` file (514 lines) loads last in the cascade to resolve visual conflicts across 25+ CSS files. It re-declares the oasis widget, sidebar, cards, buttons, typography, and motion system with definitive values, using `!important` only where needed to override earlier `!important` rules in `stitch-canonical.css` and `global-icon.css`. The `AppShell.tsx` gains scroll-direction tracking to hide the mobile bottom nav on scroll-down, and `BottomNav.tsx` accepts a `hidden` prop that drives a `data-hidden` attribute for the CSS transition. The branch also carries prior commits that tokenize raw hex values in `world-class.css` and soften the oasis panel shadow in `global-icon.css`.

**Watch for:** The bottom-nav display breakpoint in `madarek-final.css` (`min-width: 769px` hides) conflicts with `stitch-canonical.css` (`max-width: 900px` shows), creating a 769-900px window where the nav is hidden on tablets (confirmed). The nuclear `prefers-reduced-motion` rule in Section I kills *all* transitions and animations globally with `!important`, which disables the bottom-nav scroll-hide transition that Section C explicitly defines (confirmed). The TypeScript errors from the Render deploy log (`DashboardCustomizer.tsx` and `OasisWidget.tsx`) are NOT addressed by this branch — those fixes exist on `main` already, but Render deployed an older commit (likely).

## High-level view

The bottom-nav breakpoint mismatch between `madarek-final.css` (hiding at `min-width: 769px`) and `stitch-canonical.css` (showing at `max-width: 900px`) means the nav is invisible between 769px and 900px. On an iPad in portrait (810px logical), users lose their primary navigation. The intent was probably `min-width: 901px` to match the existing breakpoint.

The `prefers-reduced-motion` block in Section I uses a wildcard selector with `!important` to zero-out all animation and transition durations globally. This disables the bottom-nav transition (Section C), the card hover (Section E), button hover transforms (Section F), and page-enter animation (Section I itself). For reduced-motion users, the bottom nav teleports off-screen without warning rather than remaining visible. The scoped block in `visual-final-polish.css` Section 11 already handles bottom-nav specifically — the nuclear rule is redundant and harmful.

The bottom-nav scroll-hide CSS is declared identically in both `visual-final-polish.css` (Section 11) and `madarek-final.css` (Section C). Since `madarek-final.css` loads last and wins anyway, the earlier declaration in `visual-final-polish.css` is dead code.

The oasis widget container's `bottom: var(--sp-5)` (20px) in `madarek-final.css` applies at all viewport widths with no mobile override. A prior fix in `visual-final-polish.css` raised the widget above the bottom nav on mobile, but `madarek-final.css` overrides it by loading later at equal specificity. The widget trigger likely overlaps the bottom nav on phones.

## Bottom-nav breakpoint gap (769px to 900px)

The existing breakpoint contract is:

```
notifications.css:   .bottom-nav { display: none }       (base: hidden)
stitch-canonical.css: @media (max-width: 900px) { .bottom-nav { display: flex } }
```

The nav is visible on viewports up to 900px. `madarek-final.css` introduces:

```css
@media (min-width: 769px) {
  .bottom-nav { display: none; }
}
```

Since `madarek-final.css` loads after `stitch-canonical.css`, its `display: none` wins in the 769-900px range. The nav disappears on tablets (iPad portrait 810px, many Android tablets 800px). Changing to `min-width: 901px` aligns with the existing show-breakpoint. **Confidence: confirmed** — traced the cascade order in `main.tsx` imports and verified both rules apply at 810px.

## Reduced-motion nuclear rule

Section I declares:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

This overrides *every* transition in the application. For reduced-motion users, the bottom nav still transforms (`translateY(100%)` applies) but the transition is instant — the nav teleports off-screen without warning. The typical accessibility expectation is that spatial state changes for navigation elements either animate gently or don't happen at all; teleporting is worse than either.

The proportionate approach already exists in `visual-final-polish.css` Section 11: `transition: none !important` scoped to `.bottom-nav` only. The nuclear rule should either be removed or narrowed to target `animation-*` properties only (leaving `transition-duration` intact so each component can handle its own reduced-motion logic). **Confidence: confirmed.**

## Oasis widget mobile overlap

`madarek-final.css` sets `.oasis-widget { bottom: var(--sp-5) }` (resolves to 20px) with no media query — it applies at all viewport widths. `visual-final-polish.css` sets `.oasis-widget--ltr, .oasis-widget--rtl { bottom: calc(68px + env(safe-area-inset-bottom, 0px)) }` inside a `@media (max-width: 480px)` block.

Both selectors are single-class (specificity 0,1,0). When the element carries both `.oasis-widget` and `.oasis-widget--ltr`, both rules match and both set `bottom`. At equal specificity, cascade position wins. `madarek-final.css` loads after `visual-final-polish.css`, so its 20px value overrides the 68px mobile fix. The widget trigger will sit behind or overlapping the 60px-tall bottom nav on phones.

Fix: add a mobile media query in `madarek-final.css` Section A that raises the widget above the nav, or move the base `bottom` value into the non-mobile range only. **Confidence: likely** — confirmed cascade order; depends on the element carrying both classes simultaneously (which the JSX in OasisWidget.tsx does: `className={\`oasis-widget \${positionClass}\`}`).
