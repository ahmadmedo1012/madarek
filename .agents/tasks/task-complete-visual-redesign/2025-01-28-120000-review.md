# Complete visual redesign: CSS architecture rebuild, new color system, landing page overhaul

A ground-up rebuild of the Madarek CSS architecture, collapsing 19 stylesheets (12,394 lines) into 7 active files (2,491 lines). The color identity shifts from the previous blue palette to Navy Royal Blue (#1E3A5F) primary with Muted Gold (#C4A35A) secondary. Dark theme surfaces move from cold near-blacks to warm grays (#1a1d23 through #313742). All `color-mix()` calls are eliminated for browser compatibility, glassmorphism/backdrop-filter is removed from the landing page, and font loading drops from 4 families to 2 (IBM Plex Sans Arabic + Space Mono). The token system is simplified: 8-step spacing scale, 5-level radius, 3-level shadow hierarchy.

**Watch for:** All utility CSS classes (`.flex-col`, `.items-center`, `.gap-2`, `.text-muted`, `.font-mono`, etc.) were deleted from `utilities.css` without being migrated elsewhere — but are referenced ~800+ times across JSX components. This will cause widespread visual breakage (confirmed). The `--shadow-xl` is aliased to `--shadow-lg` and `--el-4` collapses to the same value as `--el-3`, which silently flattens any existing elevation hierarchy in non-landing pages (confirmed). Several old component styles (webinar cards, exam rows, trend bars, auth overlay) were removed from `components.css` — if any route still renders these, they'll appear unstyled (likely).

## High-level view

The file consolidation strategy is aggressive: 13 stylesheet files are emptied to single-line comments (`/* Consolidated into X.css */`) while `main.tsx` drops them from its import list. Domain-specific component styles (dashboard, notifications, owner, pdf) were migrated into `pages.css` (230 lines) — significantly less than the ~2,500 lines those files previously contained, suggesting substantial content was dropped rather than moved.

The spacing scale changes semantics at step 5+ (from 20/24/28/32px to 24/32/48/64px), which means any component using `--sp-5` through `--sp-8` will render at different sizes. Backward-compat aliases (`--space-N`) preserve names but point to the new values.

The landing page drops all glassmorphism in favor of solid surfaces with border/shadow cards, a gold CTA button, and a 70vh hero with an Islamic geometric SVG pattern background.

The utility class deletion is the single blocking issue. Over 800 class references across the React component tree (`.flex-col`, `.gap-2`, `.items-center`, `.text-sm`, `.text-muted`, `.font-mono`, etc.) no longer have corresponding CSS definitions anywhere.

## Utility class deletion: the breaking gap

The old `utilities.css` defined 70 utility classes covering flex layout, gaps, margins, text sizes, colors, and responsive visibility. The new file contains only a consolidation comment. These classes remain in active use:

```
flex-col:     86 usages
items-center: 75 usages
gap-2:        80 usages
gap-3:        47 usages
text-muted:   80 usages
text-sm:      89 usages
text-subtle: 126 usages
font-mono:    80 usages
```

Every page component — `TeacherPages.tsx`, `QualityPages.tsx`, `AdminPages.tsx`, `States.tsx` (skeleton primitives), `AnnotationsPanel.tsx` — uses these as their primary layout mechanism. Without the CSS definitions, flex containers don't flex, gaps don't space, text sizes don't apply, and color utilities show raw inherited color. This is a full-app visual regression.

## Spacing scale semantic shift

The old scale was linear (4px steps): `--sp-5: 20px`, `--sp-6: 24px`, `--sp-7: 28px`, `--sp-8: 32px`. The new scale jumps exponentially after step 4:

```
Old: 4  8  12  16  20  24  28  32
New: 4  8  12  16  24  32  48  64
```

A sidebar section using `gap: var(--sp-6)` now renders at 32px instead of 24px. Page sections using `--sp-8` jump from 32px to 64px — a doubling.

## Removed domain-specific component styles

The following component blocks were present in the old `components.css` but absent from the new version:

- `.webinar-card`, `.webinar-date`, `.speaker-chip` — workshop/webinar scheduling UI
- `.exam-row`, `.exam-row-head`, `.exam-stat`, `.exam-gaps` — exam analysis display
- `.trend-row`, `.trend-bar`, `.trend-submitted/.trend-graded/.trend-published` — admin trend visualization
- Full auth overlay system: `.auth-overlay-madarek`, `.auth-left`, `.auth-back-home`, `.auth-form-container .auth-demo`

The risk is highest for the auth flow since that's the entry point for all users.

## Landing CTA hardcoded text color

The gold CTA buttons use `color: #1a1205` — a hardcoded dark brown rather than a semantic token. If the gold token ever shifts lighter (higher luminance), the contrast ratio against this fixed text color could drop below WCAG AA. A `--gold-on` or `--on-gold` token would make this self-correcting.

## Card specification diverges from tokens

Cards use hardcoded `border-radius: 12px` and `padding: 20px` instead of the token-based `var(--r-xl)` (now 24px) and `var(--sp-5)` (now 24px). If the design system's radius or spacing tokens are later adjusted, cards won't follow. This creates a maintenance asymmetry where some components respond to token changes and others don't.
