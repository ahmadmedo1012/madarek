# Complete visual redesign: CSS architecture rebuild (v2)

The v1 review's four blocking issues have been resolved: utility classes are restored (116 lines covering flex, gap, text, spacing, and responsive visibility), `--shadow-xl` is now distinct from `--shadow-lg` in both themes, `.card` uses the `--card-radius` and `--card-padding` tokens, and table zebra-striping is back via `nth-child(even)`. The fix commit also added reveal-delay helpers, form grids, teacher profile styles, sync-page components, and a `[data-tone="surface"]` variant.

**Watch for:** 146 CSS classes referenced in JSX have no corresponding CSS definition anywhere — 107 are domain-specific component classes (annotations, leaderboard, feed, search, exam, curriculum, badges, permissions, risk rows) that existed in old stylesheets but weren't migrated into the new architecture (confirmed). The remaining ~39 include `.text-md` (12 usages), `.spin` (animation class, 2 usages), `.empty-state` (22 usages), and `.form-label` — all absent from the new CSS (confirmed). The typography scale has an ordering anomaly where `--fs-base` (16px) is larger than `--fs-md` (15px), inverting the expected sm < base < md hierarchy (confirmed).

## High-level view

The domain-specific component gap is the primary remaining concern. Styles for annotations, leaderboard, search dropdown, feed items, curriculum, exam bars, badges, risk rows, permissions, moderation, and the full auth-overlay-madarek flow existed in the old `components.css` (3,607 lines) but were not carried into any of the new files. These 107 classes back 15+ page-level features that will render unstyled.

The spacing scale semantic shift flagged in v1 remains unchanged: `--sp-5` through `--sp-8` now resolve to larger values (24/32/48/64 vs old 20/24/28/32). This is a deliberate design decision per the task spec ("8-step spacing scale"), but section-level gaps at `--sp-8` double from 32px to 64px — worth verifying visually in context.

The typography scale orders sizes as `xxs(11) < xs(12) < sm(14) < md(15) < base(16) < lg(18)`. Placing `base` above `md` inverts the semantic expectation. Components using `--fs-sm` (buttons, tables, nav) bumped from 13px to 14px — a subtle app-wide density change.

## Typography scale inversion

```
xxs: 11px → xs: 12px → sm: 14px → md: 15px → base: 16px → lg: 18px
```

The `body` element applies `font-size: var(--fs-base)` (16px), making body copy larger than anything marked "medium." The utility class `.text-md` (12 usages) would map to `var(--fs-md)` = 15px, which is now *smaller* than the body font. Consumers using `.text-md` expecting "slightly larger than base" will get the opposite effect.

## Table zebra-striping hover conflict

The restored zebra-striping applies `background: var(--surface-2)` on even rows. The hover rule also applies `background: var(--surface-2)`. On even rows, hovering produces no visual change — the row already has the hover background color. The hover state needs `var(--surface-3)` or a distinct indicator to be perceptible on striped rows.

## Card hover asymmetry

`.card.bordered:hover` gets border-color change + `box-shadow: var(--shadow-md)`. `.metric:hover` gets the same treatment. But plain `.card` (the most common variant) has no hover state at all. Some cards feel interactive while adjacent ones feel inert, despite both being clickable containers in practice.
