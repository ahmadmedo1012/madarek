# Radical CSS system replacement and landing page simplification

The entire CSS architecture—19 files totaling 12,400 lines—has been demolished and rebuilt as 8 files (4,800 lines) organized around a single token system (Navy Royal #1E3A5F + Muted Gold #C4A35A). The landing page drops from a feature showcase with AI chat demos, testimonials, and pilot results to a simple hero + stats + features + CTA pattern. All navigation, auth redirect logic, and theme toggle behavior are preserved.

**Watch for:** ~1,345 lines of owner/PDF styles live outside any CSS layer (confirmed), giving them implicit higher specificity than all layered rules—this is intentional for specificity but means future theme overrides for owner components won't work via the `@layer themes` mechanism.

## High-level view

The token system consolidates all design decisions into a single unlayered `:root` block in tokens.css, with `[data-theme='light']` and `[data-theme='dark']` selectors providing complete variable overrides. The dark palette uses warm grays (#1a1d23 base) with a lighter accent (#7EB3E0) to maintain contrast. Three shadow levels, one easing function, and eight spacing stops replace the previous proliferation of --el-*, --glow-*, and --glass-* custom properties.

The layout system (sidebar, topbar, responsive breakpoints) is extracted into its own layered file with mobile sidebar overlay triggered at 900px, colocated with the desktop layout rather than scattered across responsive.css and system.css.

The landing page drops from ~309 lines to ~250, removing the AI chat showcase, role pillars grid, testimonials, and pilot results. Nav links narrow from four (#features, #pillars, #proof, #about) to two (#features, #about)—dead anchors if anything external linked to the old fragments.

The integration pass added 83+ CSS class definitions to pages.css outside `@layer pages` so they override layered defaults without specificity hacks—but this creates a layer asymmetry with theme overrides.

## Unlayered owner/PDF styles in pages.css

Lines 1006–2350 of pages.css contain owner panel, PDF viewer, annotations, badges, chat, exam, community, and miscellaneous UI styles—all outside `@layer pages`. A comment explicitly states `"Owner Panel (appended outside layer for specificity)"`.

The consequence: any rule in `@layer themes` (the highest-priority layer) still loses to these unlayered rules due to CSS layer semantics. Today this isn't a problem because theme-dark.css doesn't override any owner-panel classes. But if a future dark-mode pass adds `[data-theme='dark'] .owner-table td { ... }` to theme-dark.css, it won't apply—the unlayered `.owner-table td` wins. Owner/PDF dark-mode adjustments must go in the unlayered section of pages.css, not in theme-dark.css.

## Dark theme shadow jump

The dark theme shifts shadow opacity from 0.05/0.08/0.12 (light sm/md/lg) to 0.2/0.22/0.25 (dark sm/md/lg). The sm shadow jumps 4x in opacity (0.05 → 0.2)—enough to make every card visibly "heavier" in dark mode even at the smallest shadow tier. Whether this is intended as a depth cue on dark surfaces or an overcorrection depends on visual testing that couldn't be performed in this environment.

## CSS class coverage without build verification

The integration pass grepped all TSX files for className references and added 83+ CSS definitions. Without `vite build` or TypeScript compilation (blocked by INTEGRATIONS_ONLY network), coverage is verified only statically. Any class spelled differently between TSX and CSS, or any CSS `var(--*)` that resolves to undefined at runtime, would not be caught. The risk is low given the thoroughness of the grep approach, but the build gap means this ships without machine-verified bundling.

## Landing page dead anchors

The nav anchor links were pruned from `#features, #pillars, #proof, #about` to `#features, #about`. The mobile menu matches. If any external link (shared URL with #pillars, university documentation) pointed to the old anchors, those fragments now lead nowhere.
