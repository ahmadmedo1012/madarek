# Quickstart — Platform Completeness Uplift

**Branch**: `011-platform-completeness-uplift` | **Date**: 2026-06-02 | **Plan**: [`plan.md`](./plan.md)

This is the engineer-facing adoption guide for the work in spec 011. Pick up a task from `tasks.md` (generated by `/speckit-tasks`) and use this file as the orientation map.

---

## What this feature is — in one sentence

Close the verifiable gaps surfaced by `madarek_audit_report00.md` (cold start, accessibility verification, English UI, real-time notifications, search Arabic-normalization, motion polish, branded loading, step-up auth on sensitive routes) without rebuilding the existing inner application.

---

## What it is NOT

1. Not a rewrite. The existing 80+ pages, JWT auth, and 60+ Prisma models stand as-is.
2. Not a new design system. Reuse `tokens.css` and the existing primitives.
3. Not a discussion forum, native app, virtual lab, certificate, or live-video feature. See spec.md "Out of Scope."

## Work-stream entry points

A workstream maps a user story to its primary touchpoints. Pick the one that matches your task.

### US1 — Verify inner-app integrity (P1)

1. Start at `frontend/src/App.tsx` route map.
2. For each authenticated route, verify (a) the page renders real data via `useResources.ts` (not placeholders), (b) the `<ProtectedRoute>` guard matches the role intent, (c) the page passes the keyboard + screen-reader smoke from US5.
3. Where a placeholder is found (e.g., admin "students/analysis/digital/settings" per `FRONTEND.md`), file a follow-up task — do **not** silently extend scope.

### US2 — Cold-start fix (P1)

1. R-001 in `research.md` is binding. Render Standard tier upgrade is a deployment change, not code.
2. Cloudflare in front of the public domain: page rules cache `/` for guests, exclude `/api/v1/*` and authenticated paths.
3. `frontend/public/splash.html` is added with inline branded markup; `index.html` references it for the early-paint slot.
4. Validate by timing TTI from a fresh incognito session after a clean redeploy.

### US3 — Shell + nav + search (P2)

1. **Sticky header**: existing `Topbar` in `components/layout/`. Add `position: sticky; top: 0; z-index: <token>;` honoring the existing `--topbar-h` token.
2. **Breadcrumbs**: new component `components/layout/Breadcrumbs.tsx`. Source path from React Router location + a static route → label registry that uses i18n keys.
3. **Search**: see `contracts/search.md`. Backend module is new (`backend/src/modules/search/`); frontend extends `lib/search.ts`. Migration `011_search_normalized.sql` adds the columns + GIN indexes + `pg_trgm` extension. Run the backfill script after migration.
4. **Desktop nav**: the existing `Sidebar` covers desktop; ensure horizontal nav for the public landing matches FR-015.

### US4 — Notifications uplift (P2)

1. Drop the 60-second poll in `useResources.ts`; subscribe to `GET /api/v1/notifications/stream` (SSE) instead. See `contracts/notifications.md`.
2. Backend: add SSE endpoint to `backend/src/modules/notifications/`; wire create/mark-read/delete to the in-process pub/sub.
3. Add `NotificationPreference` migration (see `data-model.md`).
4. Build the preferences UI on `/settings/notifications` route (new) using existing `Tabs` / `ToggleSwitch` primitives. Email-cadence controls are visible-but-disabled with a "coming soon" badge.
5. Add `Last-Event-ID` reconnect backfill in the SSE client.

### US5 — Accessibility verification (P2)

1. Wire `@axe-core/react` into `frontend/src/main.tsx` behind `import.meta.env.DEV`. R-002 specifies the exact integration shape.
2. Add `@axe-core/playwright` + `@playwright/test` to frontend devDependencies; create `frontend/tests/a11y.spec.ts` covering the in-scope route list × {light, dark} × {ar, en} = 36 cases.
3. Add `<SkipNavLink>` as the first focusable element in `<AppShell>`.
4. Audit focus indicators: ensure every focusable element gets a 3:1-contrast ring against its background. Tokenized in `interactions.css` already; verify across both themes.
5. Run the manual keyboard-only smoke from this file's checklist below for any page you touch.

### US6 — Dark mode contrast verification (P2)

1. The theme store + no-flash bootstrap already exists. Do not add a parallel mechanism.
2. Pull every text + background pair on every in-scope route into a contrast-check script (Playwright + axe handles this for us).
3. Where contrast fails in dark mode, adjust the affected token in `tokens.css` — do not patch per-component.

### US7 — English i18n (P3)

1. Install `i18next`, `react-i18next`, `i18next-http-backend`. R-003 is binding.
2. Create `frontend/src/i18n/` per the project structure in `plan.md`.
3. Migrate every literal string in JSX to `t('key.name')` — start with the global shell (`Topbar`, `Sidebar`, `BottomNav`), then per page. Add the keys to `ar.json` (canonical) and `en.json` (translation).
4. Build `<LocaleSwitcher>` and wire `PATCH /api/v1/me/locale` per `contracts/locale.md`.
5. Add `scripts/check-i18n-coverage.sh` and wire it to CI.
6. Locale resolution at first paint goes through the bootstrap inline script in `index.html` — it must run before React mounts to avoid flash-of-incorrect-language.

### US8 — Motion polish + Oasis demo (P3)

1. Existing primitives: `useReveal` (IntersectionObserver), `CountUp`. Reuse — do not re-implement.
2. Landing page sections need staggered reveal — apply `useReveal` to each `<section>` wrapper with the existing motion tokens (`--t-fast`, easing curves).
3. Branded skeleton inventory per R-008: 9 routes, co-located with each page. Reduced-motion fallback uses static tinted blocks.
4. **Interactive Oasis demo**: new lazy-loaded chunk under `components/landing/OasisDemo/`. Backend endpoint `POST /api/v1/public/oasis-demo` (unauthenticated, IP-rate-limited 3 req/min, 200-char payload cap). Autoplay first three sample exchanges before the input enables.

## Manual a11y smoke checklist

For every page you touch, run this in under 90 seconds:

1. Tab from URL bar — first focused element should be a "Skip to main content" link with a visible focus ring.
2. Tab through every interactive element. Order should match reading order. No element reachable only by mouse.
3. Activate every modal / drawer with the keyboard. Focus should trap inside; Esc dismisses; focus returns to the trigger.
4. Switch theme (light ↔ dark). No element should become invisible or low-contrast.
5. Switch locale (AR ↔ EN). No string should remain untranslated; layout should reflow without clipping.
6. Enable `prefers-reduced-motion` in DevTools. Animations should be replaced with instant transitions.
7. With a screen reader (NVDA / VoiceOver) on, every actionable element should be announced with a meaningful label.

If any step fails, fix before merge. If you can't fix it in scope, file a follow-up task and surface it in the PR description.

## Local development

The setup is unchanged from the existing `README.md` flow:

```bash
# at repo root
npm install
npm run dev:web         # Vite on :5173
npm run dev             # Express on :4000 with proxy
```

The new feature work additionally requires:

1. After pulling: `npm run db:migrate` (the three 011 migrations are additive).
2. Optional: run the search backfill once per database — `tsx backend/scripts/backfill-search-normalized.ts`.
3. After the i18n layer lands: `npm run check:i18n` (alias for `scripts/check-i18n-coverage.sh`) to verify no untranslated strings.

## Testing

| Area | Where |
|---|---|
| Frontend unit | `frontend/src/**/*.test.ts(x)` (Vitest 2.1, jsdom) |
| Frontend a11y | `frontend/tests/a11y.spec.ts` (Playwright + axe) |
| Backend integration | `backend/src/modules/<module>/__tests__/` (new — minimal happy-path coverage per the constitution) |
| i18n key coverage | `scripts/check-i18n-coverage.sh` (CI) |
| SSE | Integration test boots the server, opens an EventSource, asserts notification arrives within 1s |
| Search | `backend/src/modules/search/search.test.ts` covering the matrix in `contracts/search.md` |

The constitution requires at least integration-level happy-path + one failure path coverage on backend logic. Adhere; do not write giant test suites just to pad — write the tests that will catch the bugs you'd actually hit.

## When you're done with a task

1. Run `npm run typecheck && npm run test` at root (delegates to both workspaces).
2. Run the manual a11y smoke for any page you touched.
3. Mark the task completed in `tasks.md` and link your PR.
4. PR description must list which constitution principles the change touches (constitution principle, governance section).
5. After merge, verify the deployed state on `https://madarek.onrender.com` — you authored the merge, you own the verification (constitution VII).
